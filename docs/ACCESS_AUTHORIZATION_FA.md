> وضعیت فعال جدید: BoxAPI تنها LLM فعال است. کلید Gemini فقط حفظ شده و هیچ آزمون اتصال جدیدی برای آن انجام نمی‌شود. راهنمای اتصال و runtime در [BOXAPI_SETUP_FA.md](BOXAPI_SETUP_FA.md) است. موارد گزارش‌شدهٔ قبل صرفاً تاریخچهٔ آماده‌سازی‌اند.

# دسترسی امن والکس و لیارا — ادامهٔ پروژهٔ موجود

## نتیجهٔ بررسی واقعی

- تنظیمات و کلید قبلی Gemini حفظ شد؛ placeholderهای والکس و شناسه‌های لیارا فقط در خطوط جدید اضافه شدند. `.env` دسترسی ۶۰۰ دارد و از Git/Docker خارج است.
- حساب اعتباری طبق مستند رسمی، کیف پول، کلید API و تاریخچهٔ مجزا از حساب اصلی دارد. این قابلیت محصول تأیید است؛ تعلق کلید به طرح هکاتونِ کاربر هنوز احراز نشده است. کد هیچ endpoint خصوصی والکس را صدا نزده است.
- در پنل احراز‌شدهٔ لیارا، تیم «تیم کاو» و اعتبار **۲٬۰۰۰٬۰۰۰ تومان** دیده شد. این اعتبار ابری از سرمایهٔ معاملاتی جداست. هیچ برنامه یا منبعی ایجاد، خرید، روشن، خاموش یا restart نشد.
- CLI سراسری 6.0.2 با حساب پیش‌فرض نامرتبط وجود داشت؛ به آن دست زده نشد. نسخهٔ رسمی **9.6.0** در `.tools/liara-cli` نصب شد تا `--team-id` و `whoami` پشتیبانی شوند. حساب پیش‌فرض هیچ تغییری نکرد.
- اتصال فقط‌خواندنی **محلی**: بازار عمومی والکس موفق (۳۷۳ بازار)؛ فهرست مدل‌های Gemini با 403/PERMISSION_DENIED رد شد. از این پاسخ به‌تنهایی علت جغرافیایی نتیجه نمی‌گیریم. هیچ درخواست تولید Gemini ارسال نشده است.
- آزمون از داخل منطقهٔ استقرار هنوز **BLOCKED** است: حساب/شناسهٔ تیم و نام برنامه در CLI همین پروژه تعیین نشده و runtime پروژه‌ای در لیارا آماده نشده است. تست محلی را تست سرور نمی‌نامیم. انتخاب region ساخت برنامه، region اجرای آن را ثابت نمی‌کند.
- همهٔ ۴۴ آزمون آفلاین موفق‌اند. فایل‌های موتور استراتژی، مدل، خوراک عمومی و shadow با بستهٔ بررسی قبلی تطبیق hash دارند و تغییر نکرده‌اند.

## متغیرهای موردنیاز

| متغیر | کاربرد | وضعیت |
|---|---|---|
| GEMINI_API_KEY | اتصال مستقیم به Google، فقط catalog در تست دسترسی | مقدار موجود حفظ شد؛ 403 |
| WALLEX_API_KEY | کلید فقط‌خواندنی خود حساب اعتباری مسابقه | placeholder |
| WALLEX_CREDIT_ACCOUNT_ID | شناسهٔ همان طرح/حساب هکاتون | خالی |
| WALLEX_ACCOUNT_SCOPE | محدودکردن هدف به competition_credit | تنظیم شده؛ اثبات هویت نیست |
| LIARA_ACCOUNT | نام حساب ذخیره‌شده در CLI پس از login | خالی |
| LIARA_TEAM_ID | شناسهٔ تیم کاو در پنل | خالی |
| LIARA_APP_NAME | نام برنامهٔ اختصاصی پروژه، برای probe آینده | خالی |
| LIARA_RUNTIME_REGION | منطقهٔ اجرای واقعی که پنل نشان می‌دهد | unverified |

والکس در قرارداد بررسی‌شده از هدر X-API-Key استفاده می‌کند؛ API Secret ساختگی اضافه نشده است. برای دادهٔ عمومی والکس اصلاً کلید لازم نیست. توکن مدیریت لیارا را در `.env` برنامه یا runtime قرار ندهید؛ احراز هویت CLI از مرورگر انجام شود.

## اقدام شما در پنل والکس

۱. با حساب خود وارد شوید و در بخش اعتبار معاملاتی، **خود طرح هکاتون** را انتخاب کنید. عنوان، شناسه و تخصیص ۵ میلیون تومان را با حساب مسابقه تطبیق دهید. از کیف پول شخصی کلید نسازید.
۲. در مدیریت API مربوط به همان حساب اعتباری، یک کلید کوتاه‌مدت با نام مشخص پروژه ایجاد کنید؛ فقط مجوز مشاهده/خواندن موجودی، سفارش‌ها و سوابق موردنیاز را بدهید. معامله، ثبت/لغو سفارش، برداشت و انتقال باید غیرفعال بمانند. «اتصال به کیف پول اصلی» یا افزایش خودکار وثیقه را فعال نکنید.
۳. اگر این پنل برای طرح هکاتون کلید مستقل فقط‌خواندنی ارائه نمی‌کند، کلید کامل یا حساب شخصی جایگزین نکنید؛ قرارداد و کلید محدود را از مسئول والکس مسابقه مشخص کنید.
۴. IP allowlist را پس از مشخص‌شدن **IP خروجی ثابت runtime** تنظیم کنید؛ IP ورودی دامنه، IP مرحلهٔ build و IP موقت لپ‌تاپ جایگزین آن نیستند. اگر IP ثابت در منابع هدیه نیست، هیچ افزونه‌ای نخرید؛ ابتدا وضعیت روشن شود.
۵. کلید را فقط در `.env` همین پروژه مقابل WALLEX_API_KEY و شناسه را مقابل WALLEX_CREDIT_ACCOUNT_ID بگذارید. مقدار واقعی را در چت، Git یا دستور ترمینال ننویسید. صرف پرشدن این دو فیلد، account_scope_verified را true نمی‌کند.

## اقدام شما در پنل لیارا

۱. از منوی حساب، «تیم کاو» را انتخاب کنید و اعتبار ۲ میلیون تومان را همان‌جا ببینید. از حساب شخصی یا تیم دیگر برای استقرار استفاده نشود.
۲. برای دسترسی اولیه فقط مجوز **دیدن** سرویس پلتفرم همان تیم/برنامه کافی درخواست شود؛ مدیریت تیم، حسابداری، خرید منابع یا دسترسی به سرویس‌های نامرتبط لازم نیست. برای probe داخل runtime در آینده، مجوز مشخص خط فرمان همان برنامه لازم خواهد شد؛ با مجوز فقط دیدن قابل فرض نیست.
۳. در بخش API تیم، Team ID را مشاهده و در LIARA_TEAM_ID بگذارید. کلید کامل مدیریت لازم نیست در چت یا فایل برنامه کپی شود. هیچ کلید موجودی در این اجرا مشاهده یا چاپ نشده است.
۴. از ریشهٔ همین پروژه، ورود مرورگری را اجرا کنید:

```sh
.venv/bin/python scripts/liara_access.py login
```

ورود، 2FA و تأیید دسترسی را خودتان در مرورگر انجام دهید؛ رمز یا توکن را برای ما نفرستید. نام حسابی که CLI پس از ورود اعلام می‌کند را در LIARA_ACCOUNT بنویسید. در صورت نیاز نام‌های ذخیره‌شده بدون نمایش توکن با دستور رسمی زیر قابل مشاهده‌اند:

```sh
./.tools/liara-cli/node_modules/.bin/liara account list --columns Name --output json
```

۵. برای تأیید حساب/تیم و فهرست برنامه‌های همان تیم:

```sh
.venv/bin/python scripts/liara_access.py whoami
.venv/bin/python scripts/liara_access.py apps
```

wrapper بدون account و team صریح اجرا نمی‌شود؛ هیچ fallback به حساب پیش‌فرض شخصی ندارد. `whoami` باید عضویت در Team ID انتخاب‌شده را تأیید کند. ورود رسمی CLI credential محلی ایجاد می‌کند؛ هیچ token روی آرگومان command-line قرار نمی‌گیرد.

۶. فعلاً برنامه یا VPS جدید نسازید و پلن/افزونه نخرید. پس از مشخص‌شدن برنامهٔ اختصاصی و ظرفیت هدیه، region اجرای واقعی و نام برنامه در تنظیمات ثبت می‌شود. هیچ استفاده‌ای از IP دیگر به‌عنوان تضمین رفع 403 یا دورزدن محدودیت Google فرض نمی‌شود؛ شرایط حساب و مناطق پشتیبانی‌شده باید رعایت شود.

## تست اتصال بدون معامله

بررسی آفلاین:

```sh
.venv/bin/python -m wallex_agent.access status
.venv/bin/python -m unittest discover -s tests -v
```

بررسی محلی، فقط دادهٔ عمومی والکس و catalog BoxAPI، بدون generation:

```sh
.venv/bin/python -m wallex_agent.access probe --online --execution-site local
```

پس از استقرار مجاز روی برنامهٔ اختصاصی، تأیید تیم و آماده‌بودن runtime، همان probe از داخل برنامه قابل اجراست:

```sh
.venv/bin/python scripts/liara_access.py probe
```

در runtime فقط متغیرهای لازم برنامه و BoxAPI از بخش متغیرهای محیطی پنل تنظیم شوند؛ فایل .env یا credential CLI آپلود نشود. مسیر macOS به SSL_CERT_FILE در کانتینر لینوکسی کپی نشود؛ از CA سیستم/تصویر معتبر استفاده شود. نتیجهٔ probe باید با metadata و region اجرای واقعی در پنل تطبیق داده شود. ادعای region از یک متغیر محیطی پذیرفته نمی‌شود.

## مرز عملیاتی

TRADING_MODE=shadow، ENABLE_LIVE_TRADING=false، WALLEX_READ_ONLY=true، WALLEX_ENABLE_WITHDRAWALS=false، WALLEX_ENABLE_TRANSFERS=false و WALLEX_PRIVATE_READS_ENABLED=false باقی می‌مانند. probe در هر حالت فقط `/v1/markets` و فهرست مدل‌ها را می‌خواند و کلید والکس را حتی در درخواست عمومی نمی‌فرستد. مسیر سفارش واقعی همچنان مسدود است.
