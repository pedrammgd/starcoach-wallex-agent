# تصمیم AI با BoxAPI

BoxAPI تنها proposer فعال است؛ SDK رسمی OpenAI، Chat Completions و JSON Schema سخت‌گیرانه استفاده می‌شود. مدل اولیه `gpt-5.4-mini` یک کاندیداست؛ دسترسی واقعی، سازگاری schema و مدل منتخب پس از verify-boxapi مشخص می‌شوند. کد و کلید Gemini حفظ و از مسیر فعال خارج شده‌اند.

action فقط ENTER/HOLD/EXIT، allocation حداکثر ۰٫۲، confidence بین صفر و یک و reason محدود است. Pydantic با extra=forbid و کنترل finite/EXIT بررسی مستقل دارد. confidence کمتر از ۰٫۶۵ یا شکست provider مانع ورود می‌شود. پیشنهاد مدل هدف exposure را تغییر می‌دهد؛ risk بعد از آن سقف حجم، زیان، cooldown و deadline را اعمال می‌کند.

ورودی فقط خلاصهٔ عددی ویژگی‌ها، edge، هزینه، ریسک و exposure مجازی است؛ کلید صرافی، اطلاعات شخصی و حساب به مدل ارسال نمی‌شود. مدل اجازهٔ tool یا ثبت سفارش ندارد. timestamp بازار در prompt حذف شده تا استفاده از دانش تاریخی مدل محدود شود؛ با این حال بک‌تست LLMهای ازپیش‌آموزش‌دیده تضمین عدم نشت دانش نیست.

timeout پیش‌فرض ۲۰ ثانیه برای درخواست، حداکثر دو تلاش و خروجی حداکثر ۱۰۲۴ توکن است. retry داخلی SDK خاموش است؛ فقط 429 و 500/502/503/504 یک بار تکرار می‌شوند. timeout، خطای اتصال، احراز هویت و JSON/schema نامعتبر خودکار تکرار نمی‌شوند. metadata شامل endpoint، مدل درخواستی/برگشتی، latency، تعداد تلاش و مصرف توکن است. پیام خام خطا، header و key لاگ نمی‌شوند. قیمت برگشتی واحد تأییدشده ندارد؛ هزینهٔ USD ساخته نمی‌شود.

Agent حداکثر ۲۰ invocation و بودجهٔ رزروی یک دلار با رزرو ۰٫۰۵ برای invocation دارد؛ این برآورد جای سقف صورتحساب را نمی‌گیرد. اجرای هم‌زمان چند Agent روی یک journal پشتیبانی نمی‌شود. cache، intent پیش از درخواست و جلوگیری از تکرار درخواست مبهم پس از crash وجود دارد. لاگ SQLite زنجیرهٔ hash و export JSONL دارد.

آزمون SDK با transport شبیه‌سازی‌شده ثابت می‌کند ENTER/EXIT مدل نتیجهٔ سایه را تغییر می‌دهد و ورود در محدودهٔ پایان ریسک وتو می‌شود. این شواهد بهبود سود یا استنتاج واقعی را ثابت نمی‌کنند. فرمان احراز و مسیر گزارش در BOXAPI_SETUP_FA.md است.
